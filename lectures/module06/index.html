Part 1: Motivation — Volatility Clustering

The Limitation of ARMA

ARMA models assume the noise variance \sigma^2 is constant regardless of time.

This is clearly violated in financial returns. Consider daily S&P 500 returns:

  • 2006: annual volatility \approx 10\%
  • 2008: annual volatility \approx 40\%
  • 2020 (March): daily moves of 5–10%

No ARMA model captures this. We need a model where the conditional variance evolves over time.

Volatility Clustering in FX Returns

Our running example — the AUD/JPY carry trade — shows the same pattern. Large moves cluster in time:

Stylized Facts of Financial Returns

Stylized Fact Description
Volatility clustering Large moves tend to follow large moves; calm periods follow calm periods
Heavy tails More extreme observations than Normal predicts
Asymmetry Negative returns often trigger larger volatility increases than positive returns of the same magnitude
Uncorrelated but dependent Returns Z_t are uncorrelated, but Z_t^2 is autocorrelated

ARMA handles correlation in Z_t. GARCH handles dependence in Z_t^2.

Conditional vs. Unconditional Variance

Unconditional variance: \text{Var}(Z_t) = E[Z_t^2] — the long-run average level of volatility.

Conditional variance: h_t = \text{Var}(Z_t \mid Z_{1:t-1}) = E[Z_t^2 \mid Z_{1:t-1}]

h_t varies day by day. After a volatile Friday, Monday’s h_t should be elevated.

GARCH models h_t as a function of past data. A fitted model can provide a one-step-ahead volatility forecast \hat{h}_{t+1|t}.

Part 2: ARCH and GARCH Models

ARCH(p): Definition

AutoRegressive Conditional Heteroscedasticity (Engle, 1982):

Z_t = \sqrt{h_t}\, e_t, \quad \{e_t\} \sim \text{IID}(0, 1) h_t = \alpha_0 + \alpha_1 Z_{t-1}^2 + \cdots + \alpha_p Z_{t-p}^2

Constraints: \alpha_0 > 0, \alpha_i \geq 0 for i=1,\ldots,p.

Interpretation:

  • Large past squared returns \Rightarrow large h_t \Rightarrow large expected absolute future moves.
  • Setting all \alpha_i = 0 gives constant variance = white noise.

GARCH(p, q): Definition

Generalized ARCH (Bollerslev, 1986):

Z_t = \sqrt{h_t}\, e_t, \quad \{e_t\} \sim \text{IID}(0, 1) h_t = \alpha_0 + \sum_{i=1}^p \alpha_i Z_{t-i}^2 + \sum_{j=1}^q \beta_j h_{t-j}

Constraints: \alpha_0 > 0, \alpha_i \geq 0, \beta_j \geq 0.

Adding lagged h_{t-j} terms is like giving the variance an AR structure. GARCH(1,1) is far more parsimonious than ARCH(10) but fits almost as well in practice.

GARCH(1,1): The Workhorse

Maybe the most widely used specification in practice:

h_t = \alpha_0 + \alpha_1 Z_{t-1}^2 + \beta_1 h_{t-1}

Stationarity condition: \alpha_1 + \beta_1 < 1.

Unconditional variance: E[Z_t^2] = \frac{\alpha_0}{1 - \alpha_1 - \beta_1}

Typical values for equity returns: \alpha_1 \approx 0.05–0.15, \beta_1 \approx 0.80–0.90.

The persistence \alpha_1 + \beta_1 near 1 means volatility shocks die out slowly.

GARCH Is White Noise, Not IID

The \{Z_t\} process in GARCH is white noise: \text{Cov}(Z_{t+h}, Z_t) = 0 for h \neq 0.

Proof sketch:

\begin{align*} E[Z_{t+h} Z_t] &= E\!\left[E(Z_{t+h} Z_t \mid Z_{1:t+h-1})\right] \\ &= E\!\left[Z_t \cdot E(Z_{t+h} \mid Z_{1:t+h-1})\right] \\ &= E[Z_t \cdot 0] = 0 \end{align*}

But the squared process \{Z_t^2\} is autocorrelated:

\text{Cov}(Z_t^2, Z_{t-1}^2) = \alpha_1 \cdot \text{Var}(Z_t^2) > 0

This is why we look at the ACF of squared returns to detect GARCH effects.

ACF of Squared Returns: AUD/JPY

The raw returns show little autocorrelation, but their squares do — evidence of GARCH-type dependence:

Returns themselves are close to white noise, but the squared returns show clear, slowly decaying autocorrelation — the hallmark of volatility clustering that GARCH is built to capture.

ACF of Squared Returns: AUD/JPY

ARCH(1): Stationarity

For ARCH(1), repeated substitution shows (when \alpha_1 < 1):

Z_t^2 = \alpha_0 \sum_{j=0}^\infty \alpha_1^j \, e_t^2 e_{t-1}^2 \cdots e_{t-j}^2

From this representation:

E[Z_t] = 0, \quad \text{Var}(Z_t) = \frac{\alpha_0}{1 - \alpha_1}, \quad \text{Cov}(Z_{t+h}, Z_t) = 0

So ARCH(1) is weakly stationary (white noise) when \alpha_1 < 1, but not IID.

ARCH(1) Doesn’t Capture Long-Range Dependence

The ARCH(1) formula above shows \text{Cov}(Z_t^2, Z_{t-h}^2) \propto \alpha_1^h — a geometric decay that dies out fast. Adding a GARCH term lets that decay persist much longer:

import numpy as np
import pandas as pd
from statsmodels.graphics.tsaplots import plot_acf
import matplotlib.pyplot as plt

rng = np.random.default_rng(0)
n = 5000

# Simulated ARCH(1)
alpha0, alpha1 = 0.1, 0.3
e = rng.standard_normal(n)
z = np.zeros(n)
h = np.zeros(n)
h[0] = alpha0 / (1 - alpha1)
z[0] = np.sqrt(h[0]) * e[0]
for t in range(1, n):
    h[t] = alpha0 + alpha1 * z[t - 1] ** 2
    z[t] = np.sqrt(h[t]) * e[t]
sim_arch = pd.Series(z)

# Simulated GARCH(1,1) — same unconditional variance, high persistence
g_alpha0, g_alpha1, g_beta1 = 0.00714, 0.1, 0.85
e2 = rng.standard_normal(n)
z2 = np.zeros(n)
h2 = np.zeros(n)
h2[0] = g_alpha0 / (1 - g_alpha1 - g_beta1)
z2[0] = np.sqrt(h2[0]) * e2[0]
for t in range(1, n):
    h2[t] = g_alpha0 + g_alpha1 * z2[t - 1] ** 2 + g_beta1 * h2[t - 1]
    z2[t] = np.sqrt(h2[t]) * e2[t]
sim_garch = pd.Series(z2)

carry = pd.read_csv("../data/carry_pnl.csv", index_col=0, parse_dates=True)["carry_pnl"]

fig, axes = plt.subplots(1, 3, figsize=(15, 4))
plot_acf(sim_arch**2, lags=20, ax=axes[0], title="Simulated ARCH(1): Squared Returns")
plot_acf(sim_garch**2, lags=20, ax=axes[1], title="Simulated GARCH(1,1): Squared Returns")
plot_acf(carry**2, lags=20, ax=axes[2], title="AUD/JPY: Squared Carry P&L")
plt.tight_layout()
plt.show()

The ARCH(1) and GARCH(1,1) series have the same unconditional variance, but the ARCH(1) autocorrelations vanish after a few lags while the GARCH(1,1) autocorrelations — driven by persistence \alpha_1 + \beta_1 = 0.95 — decay much more slowly. The real AUD/JPY squared returns show the same slowly-decaying pattern as the simulated GARCH(1,1), not the fast-decaying ARCH(1) — evidence that GARCH is the better-fitting model.

ARCH(1) Doesn’t Capture Long-Range Dependence

Stochastic Volatility (for context)

An alternative that separates the latent volatility from the observations:

Z_t = \sqrt{h_t}\, e_t, \quad \{e_t\} \sim \text{IID}(0, 1) \log h_t = \gamma_0 + \gamma_1 \log h_{t-1} + \eta_t, \quad \{\eta_t\} \sim \text{IID}(0, \tau^2)

Log-volatility follows an AR(1) driven by independent noise \eta_t.

Pros: More flexible, natural latent-variable interpretation.

Cons: The likelihood is intractable — requires particle filters or MCMC.

We focus on GARCH because it has a closed-form likelihood. The straightforward MLE explains why these are way more popular in practice.

Part 4: CS 2 — Strategy Evaluation

Volatility-Scaled Positions

The GARCH(1,1) one-step-ahead volatility forecast:

\hat{h}_{t+1|t} = \hat{\alpha}_0 + \hat{\alpha}_1 Z_t^2 + \hat{\beta}_1 \hat{h}_t

Volatility targeting: scale position size inversely with forecast volatility to maintain constant risk:

w_t = \frac{\sigma^*}{\hat{\sigma}_{t+1|t}}, \quad \hat{\sigma}_{t+1|t} = \sqrt{\hat{h}_{t+1|t}}

where \sigma^* is the desired (target) daily volatility. The scaled return is w_t \cdot Z_{t+1}.

Implementing Volatility Targeting

Beware the leakage…

from arch import arch_model
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

Performance Metrics

import numpy as np
import pandas as pd

def annualized_sharpe(rets, freq=252):
    return rets.mean() / rets.std() * np.sqrt(freq)

def max_drawdown(rets):
    cum = rets.cumsum()
    return (cum - cum.cummax()).min()

raw = carry.dropna()
vol_scaled = scaled.dropna()

stats = pd.DataFrame({
    "Unscaled": {
        "Ann. Return (%)": raw.mean() * 252,
        "Ann. Vol (%)": raw.std() * 252**0.5,
        "Sharpe": annualized_sharpe(raw),
        "Max Drawdown (%)": max_drawdown(raw),
    },
    "Vol-Scaled": {
        "Ann. Return (%)": vol_scaled.mean() * 252,
        "Ann. Vol (%)": vol_scaled.std() * 252**0.5,
        "Sharpe": annualized_sharpe(vol_scaled),
        "Max Drawdown (%)": max_drawdown(vol_scaled),
    },
}).round(2)

print(stats)

Value at Risk from GARCH

GARCH also gives us a better VaR estimate than using the unconditional distribution.

Conditional VaR at confidence level \alpha:

\text{VaR}_\alpha^{(t+1)} = -\hat{\sigma}_{t+1|t} \cdot q_\alpha

where q_\alpha is the \alpha-quantile of the fitted innovation distribution (e.g., t_\nu).

from scipy.stats import t as student_t
import numpy as np
import pandas as pd

# extract GARCH params (from t-innovation fit)
nu = res_t.params["nu"]  # degrees of freedom
sigma_forecast = np.sqrt(res_t.conditional_volatility.iloc[-1])  # last fitted vol

alpha = 0.05
q_alpha = student_t.ppf(alpha, df=nu)
VaR_pct = -sigma_forecast * q_alpha
P = 1_000_000  # $1M position

print(f"1-day conditional vol:  {sigma_forecast:.4f}%")
print(f"5% conditional VaR:     {VaR_pct:.4f}%  (${P * VaR_pct / 100:,.0f})")

What We Learned: Part 2 Summary

Over Modules 3–6, we built a complete univariate pipeline for the FX carry trade:

Module Tool Key Finding
3 Stationarity, ACVF FX log returns are approximately stationary; FX levels are not
4 IID noise, random walks, sample ACF Log prices behave like random walks; returns look like white noise in the mean
5 AR/MA/ARMA Returns have minimal mean predictability (near-efficient market)
6 GARCH Volatility clustering; probably refitting this model less frequently and trusting it more than ARMA

Limitations of This Strategy/Code

  • One pair only: using AUD/JPY ignores the broader G10 carry basket.
  • Simple interest accrual: we approximate the daily carry as the annualized rate differential divided by 252, ignoring compounding and day-count conventions a live desk would use.
  • Regime changes: carry can be stable for years and then crash suddenly (e.g., 2008 “carry unwind”).
  • Transaction costs: bid-ask spreads in FX are small but nonzero, especially during stress.
  • Look-ahead bias: in-sample GARCH fit uses future information in conditional volatility calculation.

A production carry strategy would address all of these — but the analytical tools are exactly what we built here.
