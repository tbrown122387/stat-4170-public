HOW TO USE THIS RUBRIC

- Section point totals (1=10, 2=30, 3=20, 4=20, 5=20) match the assignment

- Within each section, every row lists the criterion, its point value, and what

- An attempted-but-flawed answer always scores higher than a skipped one. A
  section left blank earns 0; the same section attempted badly earns something.

  environment, with no pre-existing data cache on disk.

PART A -- PRESENTATION & REPRODUCIBILITY  (cross-cutting; deductions, max -15)
================================================================================

A1. NOTEBOOK RUNS TOP-TO-BOTTOM WITHOUT ERROR
    - Clean run, no errors: no deduction.
    - Runs with harmless warnings only (deprecation notices, solver convergence
      chatter that does not change results): no deduction.
    - One or two cells raise errors but the rest of the notebook is independent
      and gradeable: -5, and the failing section(s) are graded on their visible
      saved output only.
    - Notebook errors early and large portions cannot execute: FINAL SCORE
      CAPPED AT 60% of otherwise-earned points.
    - Not submitted as a single .ipynb (PDF only, .py only, bare Colab link with
      no notebook file): not accepted for full credit; see syllabus format/late
      policy.

A2. SELF-CONTAINED AND REPRODUCIBLE
    - Data is obtained programmatically through the Section 1 caching function;
      a grader with no cache file can reproduce the download: no deduction.
    - Depends on a local cache file that cannot be regenerated (hard-coded
      absolute path, no download code path, private/renamed file): -5.
    - Requires undocumented manual steps (install this, hand-download that): -3.
    - Random seeds are set (or results are shown to be stable without them) for
      every simulation / bootstrap / resampling step: -2 if missing AND results
      are visibly seed-sensitive.

A3. SECTION HEADINGS AND NAVIGATION
    - Every section and subsection from the prompt appears as a markdown header,
      in order, labeled so it is immediately obvious which question is being
      answered (e.g. "## Section 2.3 - Bootstrap and Rolling Window"): no
      deduction.
    - Headers present but some sub-parts are buried in code comments or not
      clearly delineated: -3.
    - No markdown structure; grader has to hunt for where each answer is: -6.

A4. FIGURES
    - All plots render inline after a clean run: no deduction.
    - Titles, axis labels, and legends (wherever more than one series is shown)
      are present on every figure: up to -5 total, scaled to how many plots are
      unlabeled. Per the prompt, unlabeled plots do not receive full credit.
    - Figures illegible (too small, overlapping, default styling that hides the
      point being made): -2.

A5. WRITTEN INTERPRETATION QUALITY
    - Prose cells actually answer what was asked, cite specific numbers and
      figures, and are in the student's own words: no deduction.
    - Interpretation is vague, generic, or just restates the question without
      engaging the results: up to -5 across the whole notebook.

A6. RETURN CONVENTION & UNITS CONSISTENCY
    - One return convention (log OR simple) is chosen, stated explicitly, and
      used consistently throughout; annualization is correct (mean x 252,
      volatility x sqrt(252); Sharpe ratios compared on a common frequency):
      no deduction.
    - Convention switched mid-notebook, or annualization errors that materially
      change reported numbers: -3 here (plus any per-section correctness loss).

A7. CODE HYGIENE
    - Reasonably organized; repeated logic is factored into functions; no dead
      cells that error; no massive copy-paste where a loop or function was
      clearly intended: no deduction.
    - Egregiously disorganized: -2.

A8. RED FLAGS (the "rookie mistakes" from the prompt) -- checked in context of
    Sections 4 and 5, deducted there, but flag them explicitly in feedback:
    - Lookahead bias / data leakage: fitting anything (scaler, hyperparameter,
      weights) on data the strategy could not have seen on that trading day.
    - Off-by-one in the trading loop: estimating with data through day t and
      then trading on day t's close instead of day t+1.
    - Reporting gross returns as if net, or applying costs at the wrong point
      in the loop.
    - Cherry-picking the flattering metric (Sharpe + cumulative return shown,
      max drawdown quietly omitted).

MAXIMUM TOTAL PART A DEDUCTION: -15 (A1 hard caps apply on top of this).
